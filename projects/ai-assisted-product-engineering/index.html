Summary

My contribution was the engineering direction and judgment around agent implemented code: define the product objective, review the proposed solution, direct changes, and oversee validation.

PULSE's onboarding iteration provides a concrete example. Research informed changes to registration, guidance, and game pace. Coding agents implemented the changes under my direction, with architecture and function review, pull request review, unit tests, and integration testing in the delivery workflow.

Delivery workflow

  1. User signal and product decision
  2. Specification and agent implementation
  3. Pull request review and validation
  4. Release and production feedback

User Signal and Product Decision

I built the internal analytics used to identify friction and measure product changes: acquisition and activation funnels, configurable user flow analysis, cohort retention, repeat authentication milestones, and bottleneck reports. Administrators could select which actions to track and inspect the flows between them. I used those reports alongside A/B tests, community feedback, and user research. For onboarding, the outcome that mattered was whether a first time user completed their first lineup.

The resulting changes moved registration until after initial play, replaced the tutorial with a milestone system, and adjusted the pace and speed of actions. This let users experience the game before committing to registration and gave them guidance through progress.

Engineering Workflow

The workflow used agents from product ideation and specification through implementation, debugging, and validation. Coding agents handled the implementation; I reviewed the architecture and functions, assessed pull requests, and told the agents which approaches and changes to adopt.

01

Define the change

I used the analytics reports and user feedback to frame the problem and product objective. Agents helped develop specifications and implementation steps.

02

Direct implementation

Coding agents implemented the changes against specifications. I reviewed architectural decisions and directed which approaches to adopt.

03

Test and review

I reviewed functions and pull requests and oversaw validation, including unit tests and integration testing.

04

Operate and learn

I owned releases, monitoring, production support, and defect investigation. The analytics I built and user feedback informed subsequent work.

This is a summary of my delivery practice, not a reproduction of an individual ticket, pull request, or release log.

Verification and Ownership

Validation included unit tests and integration testing. Function and pull request review let me assess the implementation alongside its architectural fit and direct the agent on which changes to adopt.

Engineering verification and product validation answered different questions. Tests and review addressed whether the implementation behaved as intended. The product reports let me examine activation and subsequent return behavior. A passing test suite did not, by itself, establish that a product decision improved those outcomes.

I remained responsible for operating the resulting system. At PULSE, that included daily releases, monitoring, defect investigation, data recovery, and user support.

Engineering principle

A clear specification gives an agent a target. Tests and review provide evidence about its implementation. Production feedback shows whether the original product decision was useful.

Outcome and Limits

The onboarding changes increased the share of first time users completing their first lineup by 236%.

This is the reported relative improvement from the combined onboarding changes. It is not a percentage point increase, a result attributed to AI alone, or a measured gain in engineering speed. The public case study does not include the underlying cohort sizes or measurement window.

The lesson is to keep responsibility connected across the whole process: identify the user problem, define the change, review its implementation, and evaluate what happens after release. Agent assistance belongs inside that process.
