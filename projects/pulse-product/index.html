Executive Summary

PULSE was built to make online football management feel like a living world rather than a collection of menus and statistics. The game combined a persistent football world, scheduled fixtures and simulations, real time frontend updates, mobile delivery, and AI generated post match news grounded in game data.

My responsibility connected game and schema decisions, agent implementation, testing, release, monitoring, defect investigation, data recovery, and user support. I also built the internal analytics used to prioritize product changes and measure improvement. During my involvement, the production system processed an average of approximately 28,000 user triggered game actions per day.

Game and Pixel Level UX

The game covered scheduling, leagues, cups, tactics, player development, reports, transfers, and support tooling. I designed the responsive behavior and iterated individual screens using game instrumentation, funnel analysis, A/B tests, community feedback, and direct observation of user friction.

Measured game decision

Research and feedback led me to defer registration until after initial play, replace the tutorial with a milestone system, and adjust the pace of actions. Coding agents implemented the changes under my direction. Together, the onboarding changes increased the share of first time users completing their first lineup by 236%, a relative improvement rather than a percentage point increase.

Product Analytics for Optimization

I built internal acquisition and activation funnels, configurable user flow analysis based on actions selected by an administrator, season based cohort retention, repeat authentication milestones, and bottleneck reports. These tools exposed where visitors stopped, whether they reached meaningful play, and whether they returned.

I used the reports as input to product optimization and to measure improvement. Traffic filters and explicit activity definitions made the population and behavior being measured visible. The analysis complemented community feedback, user research, and A/B tests.

Systems + Production Operations

I designed the application database, schemas, backend logic, Node.js REST APIs, admin tooling, and real time workflows backed by PocketBase. Scheduled jobs advanced fixtures and simulations, then delivered the resulting state changes to the frontend in real time. User actions included lineup changes, substitutions, transfers, training, navigation, and club decisions. Each action updated the relevant database and frontend state.

I shipped the mobile game with Capacitor and owned Docker delivery, Linux operations, DigitalOcean, AWS S3, monitoring, releases, investigation, and recovery.

An Agentic Newsroom Inside the Game

To make simulated matches feel like events in a living football world, I built a scheduled newsroom pipeline that published one human approved post match article per day to real PULSE users.

01

Game data

Schema aware tools retrieved simulated match events, player statistics, team context, and previous results from the game database.

02

Journalist

A journalist agent searched the available events and context for stories worth developing.

03

Editor

An editor agent reviewed the candidates and selected the story that should be written.

04

Writer and review

The writing stage drafted the article, then a human approved it before publication.

Cost architecture

Python and deterministic scripts handled data retrieval, filtering, and preparation. Models were reserved for editorial judgment and creative writing. Model generation cost was measured in cents per story; human review time was the larger operating cost.

The next planned stage was club specific storytelling, live match commentary, and narrative interactions that could influence gameplay.

Outcome + Business Impact

During my involvement, PULSE became a live web and mobile game with scheduled simulations, measurable product iteration, production operations, and an agentic newsroom. The remaining team continues its development.
