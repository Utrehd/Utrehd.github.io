Executive Summary

The program developed reusable software, embedded device foundations, and edge products that connected existing machines to modern factory systems without requiring factories to replace working equipment.

It was a partially government funded collaboration between Eaton and the Czech Institute of Informatics, Robotics and Cybernetics at the Czech Technical University. I led five engineers and two interns across projects with budgets up to approximately $1.2 million. I led product direction, agile delivery, stakeholder alignment, and direct engineering. This meant I could carry a factory problem from discovery through product definition, implementation, and validation.

Product Direction

My first responsibility was to determine what factories actually needed. I visited technicians, factory directors, and workers, then translated their operating constraints into a product roadmap and feature set.

01

Study the market

Assessed technologies, competing approaches, customer needs, and profitability before committing engineering capacity.

02

Define the portfolio

Converted the findings into product concepts, feature priorities, roadmaps, and maturity targets.

03

Run the program

Led agile planning, set priorities, coordinated the team, and prepared funding and government documentation.

04

Align stakeholders

Brought proposals into discussions with product management, executives, sales, customers, and contributing departments. We agreed the final priorities together.

Installation finding

Plant research showed that installation had to be simple. An electrician should be able to set up a gateway or data collector through guided steps, without knowing TCP/IP or writing code. Advanced settings could stay in a separate administration view.

Edge Product Portfolio

The program was a portfolio, not a single gateway. Each product addressed a different part of the path from embedded device communication to useful factory information and local control.

Gateway and data

Connect existing machines

Developed gateway and data collector concepts with digital and analog I/O, OPC UA, MQTT, HTTPS, Azure SQL, MES, and scheduling interfaces.

PLC connectivity

Publish reusable software

Developed the CODESYS MQTT client library in alignment with IEC 61131 and released it through the CODESYS Store.

Local control

Move logic toward the field

Created a distributed local control concept that could execute simple behavior within intelligent field I/O.

Device platform

Build the SmartWire-DT foundation

ASIC2 was Eaton's second generation application specific chip for SmartWire-DT. Its dual core Arm Cortex-M0+ architecture separated protocol communication from device application logic and became the shared ASIC foundation across the SmartWire-DT device family.

Hands on Engineering

For the embedded OPC UA gateway, I worked as product manager and directly tested the software and hardware. I did not implement the OPC Foundation SDK or the FreeRTOS integration.

My ASIC2 contribution had a different boundary. I mainly managed the chip and embedded software library workstream, including priorities, coordination, and delivery. My direct source contribution was limited to targeted bug fixes and small modules. The silicon architecture and complete communication stack were team outputs, not work I claim as mine alone. Eaton's current SmartWire-DT documentation still exposes the ASIC firmware as part of each module's hardware information.

The distributed Local Control Function, known internally as LCF, shows the depth of that work. I worked with Oxana Kovbasjuková on the function and led her initial internship at Eaton. We built a browser based function block programming application, a Python compiler that generated instructions for a stack machine, and an embedded C interpreter that executed the logic on an ASIC2 based SmartWire-DT I/O target.

Factory Validation

The pilots were not the final product. They were the validation method. We used real machines and real factory interfaces to test whether the portfolio solved the installation, connectivity, and information problems identified during discovery.

01

Connect machines

Retrofitted approximately 12 live machines with physical I/O connectivity and digital twins across three production plants.

02

Model useful state

Mapped cycle time, operating state, faults, performance, and utilization into consistent machine data.

03

Supply factory systems

Moved operational data through OPC UA, MQTT, HTTPS, and Azure SQL toward MES and scheduling systems.

04

Test installation

Used technician feedback to refine the setup concept and separate guided tasks from advanced administration.

Outcome and Evidence Boundary

The program produced a validated product direction, reusable software, one published library, the ASIC2 chip and embedded software foundation, and direct evidence from real factories.
